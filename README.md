# 旬理論 日本株スクリーナー v1.0

業種・テーマの資金集中の兆候を探し、その中から高値更新・押し目反発候補を毎日抽出するプログラムです。発注は行いません。Python 3.11以上で実行します。

**完成範囲：** J-Quants V2の取得処理、33業種と手動テーマ分類の判定、個別銘柄の選定、参考リスク計算、日付別レポート、日次実行設定、架空データによるテスト。
**未実施：** APIキーを用いた実相場での接続試験、収益性のバックテスト、運用先への設置。付属のデモは架空企業・架空相場です。

## 1. 最短の動作確認

ZIPを展開し、`shun-japan` フォルダに移動します。

```bash
python -m pip install -r requirements.txt
python shun.py --demo
```

`demo_reports/2026-01-30/report.md` を開いてください。APIキーは不要です。デモの日付は営業日風の合成系列で、日本の祝日は再現しません。実運用は取引所カレンダーを使用します。

## 2. 実データで実行

1. [J-Quants](https://jpx-jquants.com/)で、直近の日次株価と約280営業日の履歴を取得できる契約・APIキーを準備します。利用可能期間・遅延・料金は契約画面で確認してください。古いデータしか取得できるプランでは当日用レポートを作れません。
2. APIキーを環境変数に登録します。ソースやGitHubに直接書き込まないでください。
3. 次のコマンドを実行します。

macOS / Linux:

```bash
export JQUANTS_API_KEY='自分のAPIキー'
python shun.py
```

Windows PowerShell:

```powershell
$env:JQUANTS_API_KEY='自分のAPIキー'
python shun.py
```

初回は約280営業日分の全銘柄データを取得します。数分〜数十分かかり、APIのレート制限・ネットワークによって長くなる場合があります。2回目以降はキャッシュを再利用し、最新5営業日を取り直します。全期間の訂正反映には `python shun.py --refresh` を使用してください。新規上場銘柄は210営業日分揃うまで対象外です。

日本時間20時前の実行は前営業日、20時以降は当日（休場日なら直前営業日）を対象にします。20時はこのプログラムの保守的な選択基準であり、データ提供時刻の保証ではありません。対象日が未提供の場合は古い日を「最新」と表示せず、エラー停止します。

```bash
python shun.py --date 2026-10-23
```

日付指定はその日以前の直近営業日です。過去のレポート作成時も指定日付のマスターを取得しますが、これはバックテストではありません。

## 3. 毎朝の自動実行（GitHub Actions）

付属 `.github/workflows/daily.yml` は**日本時間の月〜金6:40**に起動する設定です。未設置なので、このファイルを受け取っただけでは自動運転は始まりません。

1. 自分の非公開GitHubリポジトリを作成します。
2. `shun-japan` の中身をリポジトリ直下に置きます。`shun.py`、`requirements.txt` と `.github/workflows/daily.yml` の位置に注意してください。外側のフォルダを丸ごと一段下に置かないでください。
3. Settings → Secrets and variables → Actions → New repository secret から、名前 `JQUANTS_API_KEY`、値にAPIキーを登録します。
4. デフォルトブランチにファイルを保存し、Actions → Shun Japan Daily → Run workflow で初回実行します。
5. 実行後の Artifacts → shun-report-… をダウンロードすると、日付別のCSV・レポートが読めます。

GitHubのスケジュールは遅延する場合があり、定刻の配信は保証されません。休場日の朝も直前営業日のレポートを再計算します。これはメール・LINE・ChatGPTへの通知設定ではありません。iPhoneだけでプログラムを常駐実行する方式ではなく、GitHubの実行環境を使います。データの利用・保存・共有は契約条件に従ってください。

PCで常時実行する場合はOSのタスクスケジューラで `python shun.py` を毎朝起動しても構いません。環境変数がスケジューラにも渡ることを確認してください。

## 4. 旬理論を数値に置き換えた部分

| 旬理論の要素 | 実装 |
|---|---|
| 資金の向かう方向 | 売買代金5日平均÷その前20日平均、当日代金÷前20日平均 |
| 他の銘柄より買われる | 5日・20日騰落率と全有効銘柄中央値との差 |
| テーマ全体への波及 | 構成銘柄の20日線上比率・相対強度プラス比率 |
| 認識が変わる局面 | 当日終値が前日までの20日高値を更新し、代金増加を伴う |
| 押し目の確認 | 上向き20日線付近で前日比プラス、直近代金増加 |
| 旬の移り変わり | 5営業日前と同じ計算を比較。初動・継続・過熱・失速 |
| 規律 | 追随回避・流動性制限・参考損切り・損失予算・集中制限 |
| 鋼のメンタル | 判定ルールを固定し、毎日同じ形式で理由を記録 |

売買には必ず買い手と売り手がいるため、売買代金の増加は純資金流入の証明ではありません。signed5も「日次騰落方向×売買代金」の比率であり、買い注文・売り注文を識別した値ではありません。

ニュースの鮮度、SNSの熱狂、投資家の心理、空売りの踏み上げを直接判定する機能はありません。この版は**価格・売買代金による第一段階の候補抽出**です。物語の事実確認は抽出後に行います。

### 個別スコア（100点）

- 5日相対強度の順位：25点
- 20日相対強度の順位：20点
- 5日売買代金倍率の順位：20点
- signed5の順位：10点
- 20日線上：10点
- 200日線上：5点
- 前20日高値更新：10点

順位は有効ユニバース全体のパーセンタイルです。各点数は上昇確率を意味しません。

### 業種・テーマスコア（100点）

`個別スコア中央値×0.45 + 20日線上比率×25 + 相対強度プラス比率×15 + clip((代金倍率中央値−1)/0.5, 0, 1)×15`

原則3銘柄以上、データ充足率70%以上のグループのみ判定します。売買代金で大型株に過度に引っ張られないよう、中央値と騰落の広がりを使います。グループの「代金倍率」は構成銘柄倍率の中央値であり、グループ売買代金合計の倍率ではありません。

### 局面判定（上から優先）

1. 20日線から20%超乖離した銘柄が40%以上：過熱。
2. 5日相対強度中央値がマイナスかつ代金倍率1未満、または5営業日で旬スコア12点以上低下：失速。
3. スコア60以上、相対強度プラス、代金倍率1.1以上、20日線上55%以上：旬。5営業日前が60未満なら初動、それ以外は継続。
4. それ以外：監視。必要データ不足：判定不足。

### 個別のエントリー候補

共通条件は、旬の業種またはテーマに属すること、スコア65以上、200日線上、当日と前20日平均の売買代金が各2億円以上です。

- 高値更新候補：終値で前20日高値更新、当日代金1.5倍以上、終値が日中値幅の上位35%以内。
- 押し目反発候補：20日線乖離−2〜+5%、20日線が5営業日前より上、前日比プラス、5日代金倍率1.1以上。
- 過熱：20日線乖離+20%超、5日+25%超、または当日ストップ高到達フラグ。この場合は候補から除外。
- 失速：20日線割れに加え相対強度マイナスまたは代金倍率1未満。保有しているなら撤退点検対象。
- 市場全体で20日線上が40%未満なら、新規候補をゼロにします。

同一銘柄は1回のみ、同一業種および有効な旬テーマあたり最大3銘柄、全体最大10銘柄です。参考配分上限や100株単位のため、点数順の上位銘柄でも採用されない場合があります。株価が高く100株を配分内で買えない銘柄は監視一覧に残ります。

## 5. 初期設定の調整

`config.json` を編集します。例：

| キー | 初期値 | 意味 |
|---|---:|---|
| min_value | 200000000 | 売買代金下限2億円 |
| top_n | 10 | 最大候補数 |
| per_group | 3 | 同一分類の候補数上限 |
| stop_pct | 0.05 | 約定価格からの損切り幅の仮定 |
| capital | 1000000 | **計算例用の資金100万円。実際の資産額ではありません** |
| risk_pct | 0.005 | 1銘柄の想定損失予算0.5% |
| max_position_pct | 0.10 | 1銘柄の配分上限10% |
| max_basket_pct | 0.30 | 今回候補全体の配分上限30% |
| lot | 100 | 参考株数の単位 |

参考株数は「許容損失÷（終値×損切り率）」と「配分上限÷終値」の小さい方を単元単位で切り捨て、さらにバスケット上限で制限します。既存の保有株、手数料、スリッページは反映していません。ギャップダウンやストップ安では損切り価格で約定せず、想定損失を超えることがあります。呼値・実際の単元・価格は発注前に確認してください。

時価総額、黒字、1年+30%は必須条件にしていません。旬理論の小型株・初動・赤字テーマ株を除外しすぎないためです。ただし上場直後のIPOは長期線不足で除外されます。

## 6. テーマの分解・更新

`themes.csv` は手動の分類表です。AI電力インフラ、半導体、防衛の初期例を入れています。公式なテーマ分類や網羅的な関連銘柄リストではなく、関連の強さも未採点です。銘柄の事業変更に応じて更新してください。分類すること自体は推奨・旬認定ではありません。

```csv
Code,Theme,Subtheme
65010,AI電力インフラ,重電
65040,AI電力インフラ,電力設備
65080,AI電力インフラ,変電設備
```

4桁・英字入り4文字コードは末尾0を補います。同じ銘柄に複数テーマを付けられます。Subthemeは分類管理用メモで、この版の独立採点には使いません。宇宙・ドローン・量子等を加えるときは、各テーマ3銘柄以上を登録します。未登録テーマの自動発見は行いません。33業種の抽出はテーマ表に依存せず毎日実行されます。

## 7. 出力と再現性

`reports/YYYY-MM-DD/` に保存します。

- `report.md`：日本語レポート
- `groups.csv`：全業種・登録テーマの順位と局面
- `stocks.csv`：全有効銘柄の指標・根拠・監視判定
- `picks.csv`：参考配分を含む採用候補（0件も正常）
- `metadata.json`：分析日、実行時刻、設定、充足率

`cache/YYYY-MM-DD.json` に取得データを保持します。同日再実行はその日の出力を更新します。入力訂正前の版を恒久保存する仕組みではありません。完全再現が必要なら入力・設定・分類表を別途日付付きで保存してください。

CSV入力にも対応します。

```bash
python shun.py --csv-dir mydata --date 2026-10-23
```

必要ファイル：

- `master.csv`: Code,CoName,S33Nm。対象日当時の普通株式マスターを用意。
- `prices.csv`: Date,Code,O,H,L,C,Va,AdjFactor。日付YYYY-MM-DD。OHLCは調整前、売買代金は円。最低215営業日以上を推奨。ULは任意。
- `calendar.csv`: Date,HolDiv。1=東証営業日、2=半日、0/3=現物休場。

CSVモードはオフライン分析用です。最新性・マスターの市場範囲は入力者が保証してください。基準日が古い場合も、その日付を明示して出力します。

## 8. 品質確認と制約

```bash
python -m unittest discover -s tests -v
```

株式分割、将来データの排除、当日欠損、部分配信、重複、前日までの高値、小規模テーマ、失速市場、資金配分・過熱、休場日、APIページングをテストします。ネット接続試験ではありません。

価格は調整前OHLCと分析日までの調整係数から再構成します。異なる取得日時の調整済み価格を継ぎ足すと分割時に不整合が出るためです。配当込みリターンではなく、APIが対応しない企業行動は補正できません。出来高調整の特殊ケースを避け、スコアの活動量には実売買代金を使います。

全体充足率70%未満なら停止し、個別欠損を前日値で埋めません。欠損銘柄・IPOの除外自体に偏りが生じることには注意が必要です。過去のテーマ分類表・構成銘柄・データ訂正履歴を復元していないため、そのまま収益率のバックテストには使わないでください。

利益率だけの一律利確や、自動的な長期投資への切替は実装していません。保有価格・建玉・最高値を追跡するポジション管理、アンカー株への実際の資金移動、通知、ニュース分析は別機能です。
